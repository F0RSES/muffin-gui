# Muffin
Cross-platform Qt6 GUI for zapret (Windows winws + Linux nfqws).

[![CI](https://github.com/F0RSES/muffin-gui/actions/workflows/ci.yml/badge.svg)](https://github.com/F0RSES/muffin-gui/actions/workflows/ci.yml)

## Что это
Графическая оболочка для запуска и управления стратегиями zapret.
Тёмная/светлая тема, карточки стратегий, live-логи, ping-индикаторы,
системный трей.

## Зависимости
- Qt 6.6+ (Widgets, Network, Test; без Concurrent — модуль не используется)
- CMake 3.21+
- Windows: MSVC 2022 (Visual Studio 17) — проверено в CI
- Linux: GCC 11+ или Clang 15+ — проверено в CI (ubuntu-22.04, GCC 11)

Протестировано на Qt 6.7.3 (CI: Ubuntu 22.04 и Windows Server 2022)
и Qt 6.10.2 (локальная разработка на Kali Linux).

## Сборка
    ./scripts/build.sh

## Источники zapret
- Windows: https://github.com/Flowseal/zapret-discord-youtube
- Linux:   https://github.com/bol-van/zapret

Кнопка «Скачать zapret» (тулбар, настройки, экран «стратегии не найдены») запрашивает последний
релиз у GitHub, сверяет опубликованный SHA-256, распаковывает архив системным средством (`tar`/`tar.exe`,
`unzip` как запасной вариант — сторонних библиотек нет) и устанавливает дерево в
`<AppDataLocation>/zapret`, то есть на Linux в `~/.local/share/F0RSES/Muffin/zapret`, на Windows в
`%APPDATA%\F0RSES\Muffin\zapret`. Эта папка добавлена в автопоиск, поэтому она будет найдена после
перезапуска GUI даже при пустых настройках.

Существующая папка заменяется только после проверки новой: при несовпадении хеша, обрыве скачивания,
отсутствии архиватора или неожиданной структуре релиза прежняя установка остаётся на месте. `.rar`
из релиза не берётся — его не умеет распаковать ни один архиватор, входящий в ОС.

## Запуск на Linux

Скачанный через GUI архив zapret — это распакованное дерево, а не установленная система. У него нет
файла `config` в корне, а `init.d/sysv/functions` source-ит его самым первым действием
(`. "$ZAPRET_CONFIG"`), поэтому `pkexec <скрипт> start` падает ещё до чтения каких-либо опций. Такую
карточку GUI не показывает: остаётся одна рабочая — **nfqws (portable)**, в которой правила NFQUEUE
создаёт и удаляет сама оболочка. `install_easy.sh` создаёт `config` — и карточка «zapret» вернётся при
следующем сканировании (а построив `nfq/nfqws`, она встанет и выше portable-режима).

Portable-режим передаёт nfqws флаг `--user=root`. Это не опция, а необходимость: попав в root, nfqws
по умолчанию сам сбрасывает права на uid `0x7FFFFFFF` (в логе это видно как
`Running as UID=2147483647 GID=2147483647`), и делает это **до** создания очереди —
`nfq_create_queue(): Operation not permitted`, exit 1, при уже вставленных правилах. У nfqws нет
флага «не сбрасывать», поэтому используется `--user=root` — тот же приём, что у самого zapret
(`USEROPT="--user=$WS_USER"`): сброс происходит на uid 0, то есть никуда, и `CAP_NET_ADMIN` доживает
до создания очереди. Флаг добавляется только когда дочерний процесс действительно root; собственный
`--user=` или `--uid=` пользователя не перезаписывается.

## Переход с 0.1.0 (переименование организации)

До 0.1.1 организацией приложения называлась так же `Muffin`, и Qt писал это имя в путь дважды:
`~/.local/share/Muffin/Muffin` на Linux, `%APPDATA%\Muffin\Muffin` на Windows. Первый запуск новой
версии делает перенос один раз, до чтения любых путей и настроек:

- скачанное дерево переносится в папку текущей идентичности одним `rename` (не копированием); пустые
  папки-оболочки `Muffin/Muffin` удаляются, но только если в них действительно ничего не осталось;
- значения из старого хранилища настроек (`~/.config/Muffin/Muffin.conf` на Linux, реестр HKCU старой
  организации на Windows) переносятся в новое, и записанные в них пути, указывающие на перемещённую
  папку, переписываются на новое место;
- ничего не перезаписывается: если в новой папке уже лежит дерево zapret, перенос не делается и старое
  остаётся на месте; если в новом хранилище есть хотя бы одно значение, импорт настроек пропускается.

Старое хранилище не удаляется — его можно удалить вручную, когда убедишься, что всё на месте.
